개인화 마이데이터 앱 아키텍처 (The Big Picture)
아래 그림은 우리 앱의 전체 구조와 데이터 흐름을 시각적으로 표현한 것입니다.

각 구성 요소의 역할
Electron (전체 앱의 껍데기 및 관리자)

역할: 사용자가 실행할 .exe 설치 파일을 만듭니다. 앱의 창(Window)을 생성하고, 전체적인 생명주기(시작, 종료)를 관리합니다.
주요 임무:
앱이 시작될 때, 보이지 않는 곳에서 Python 백엔드 프로세스를 실행시킵니다.
사용자에게 보여줄 UI(웹 페이지)를 창 안에 로드합니다.
UI와 Python 백엔드 사이의 안전한 다리(통신 채널) 역할을 합니다.
앱이 종료될 때, 실행했던 Python 프로세스를 깔끔하게 종료시킵니다.
프론트엔드 (UI, 사용자의 눈과 손)

기술: HTML, CSS, JavaScript (React나 Vue 사용 추천)
역할: 사용자가 직접 보고 상호작용하는 모든 화면을 담당합니다. (대시보드, 차트, 달력, 버튼, 입력 폼 등)
주요 임무:
사용자 행동(버튼 클릭, 이미지 업로드 등)을 감지합니다.
필요한 작업(예: "이 이미지 OCR 해줘!")을 Electron을 통해 Python 백엔드에 요청합니다.
백엔드로부터 받은 데이터(JSON)를 이용해 화면을 동적으로 업데이트합니다. (예: 차트 다시 그리기, 목록에 새 항목 추가)
백엔드 (Brain, 실제 일꾼)

기술: Python (Flask 또는 FastAPI 프레임워크 사용)
역할: 눈에 보이지 않는 곳에서 모든 핵심 로직과 계산을 처리합니다. UI가 없습니다.
주요 임무:
프론트엔드의 요청을 받아, y_predict.ipynb에서 구현한 OCR 및 데이터 구조화 로직을 실행합니다.
**SQLite 데이터베이스에 데이터를 저장(INSERT), 조회(SELECT), 수정(UPDATE), 삭제(DELETE)**하는 모든 작업을 전담합니다.
대시보드에 필요한 통계 데이터를 DB에서 집계(GROUP BY, SUM 등)하여 계산합니다.
처리된 결과를 JSON 형태로 프론트엔드에 돌려줍니다.
데이터베이스 (Memory, 영구 저장소)

기술: SQLite
역할: 모든 거래 내역, 사용자 설정, 카테고리 등을 저장하는 앱의 '기억'입니다.
주요 임무:
사용자의 PC 내 안전한 폴더(예: 내 문서)에 my_data.db 같은 단일 파일로 존재합니다.
오직 Python 백엔드만이 이 파일에 접근하여 데이터를 읽고 씁니다. (보안상 매우 중요한 원칙)
대표적인 작업 흐름: "이미지 업로드로 내역 추가하기"
사용자: 앱 화면에서 '이미지 업로드' 버튼을 클릭하고 은행 앱 캡처 화면을 선택합니다.
프론트엔드(UI): 선택된 이미지 파일을 Electron을 통해 백엔드(Python)로 전달하며 "OCR 처리해줘"라고 요청합니다.
백엔드(Python): 이미지 파일을 받아 ML 모델을 실행하고, 거래 내역을 추출/정제합니다.
백엔드(Python): 정제된 거래 내역 데이터를 로컬 SQLite DB 파일에 저장(INSERT)합니다.
백엔드(Python): "성공적으로 처리했고, 추가된 데이터는 이것이야" 라는 응답을 JSON 형태로 프론트엔드에 보냅니다.
프론트엔드(UI): 응답을 받고, 화면의 거래 내역 목록과 대시보드 차트를 새로운 데이터로 업데이트하여 사용자에게 보여줍니다.
